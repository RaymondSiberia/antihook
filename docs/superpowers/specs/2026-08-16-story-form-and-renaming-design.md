# Дизайн: переименование сайта и форма «Рассказать о случае»

## Цель

Обновить позиционирование сайта и добавить безопасную демонстрационную форму, через которую посетитель может описать свой случай и оставить предпочтительный способ связи. На этом этапе данные не отправляются и не сохраняются.

## Изменения текстов

- Название бренда в шапке и футере: `СО МНОЙ НЕ СЛУЧИТСЯ`.
- Доступное название ссылки на главную: `Со мной не случится — на главную`.
- Заголовок первого экрана: `Уверен, что с тобой такого не случится?`.
- Заголовок страницы и статической версии GitHub Pages: `Со мной не случится — тест на устойчивость к вербовке/манипуляциям`.

Остальные тексты теста и структура лендинга не меняются.

## Точки входа

Кнопка `Рассказать о случае` размещается:

1. в шапке перед ссылкой `Куда обратиться`;
2. в футере рядом со ссылкой `Наверх`.

На мобильном экране кнопка остаётся доступной. Обе кнопки открывают одно и то же модальное окно и используют общий обработчик.

## Модальное окно

Форма оформляется в существующем визуальном стиле: светлая карточка на затемнённом фоне, тёмные подписи, оранжевые и лаймовые акценты, выраженная тень.

Модальное окно:

- имеет заголовок `Рассказать о случае`;
- закрывается крестиком, кликом по фону и клавишей Escape;
- удерживает фокус внутри во время работы;
- возвращает фокус на кнопку, из которой было открыто;
- блокирует прокрутку страницы;
- при закрытии очищает введённые значения, чтобы чувствительный текст не оставался на устройстве в состоянии страницы.

## Поля формы

Все поля обязательные.

### Способ связи

Поле `Куда прислать ответ?` — выпадающий список с пустым начальным значением и вариантами:

- `Мессенджер`;
- `Почта`;
- `Телефон`.

После выбора показывается ровно одно дополнительное поле:

- `Мессенджер` → `Аккаунт в соцсети`, обычное текстовое поле;
- `Почта` → `Твоя почта`, поле типа email;
- `Телефон` → `Твой номер телефона`, поле типа tel.

При смене способа связи значение предыдущего контактного поля очищается.

### Описание случая

`Поделись своим случаем` — многострочное текстовое поле. Поле принимает свободный текст и не имеет счётчика символов на этом этапе.

### Отправка

Кнопка формы называется `Рассказать`. При отправке:

1. проверяется выбор способа связи;
2. проверяется заполнение соответствующего контактного поля;
3. для почты применяется стандартная браузерная проверка формата;
4. проверяется заполнение описания случая;
5. при успехе форма заменяется экраном благодарности.

Экран благодарности сообщает только: `Спасибо, что поделился`, без дополнительных пояснений. Данные не отправляются и не сохраняются. После закрытия окно возвращается в исходное состояние.

## Ошибки

- Ошибка показывается рядом с конкретным полем и связывается с ним через `aria-describedby`.
- Первое поле с ошибкой получает фокус.
- Ошибка исчезает после исправления значения и повторной отправки.
- Сетевые ошибки отсутствуют, поскольку форма не выполняет запросов.

## Архитектура

Форма выделяется из большого компонента страницы в отдельный клиентский компонент `StoryFormDialog`.

Компонент отвечает только за:

- открытие и закрытие окна;
- состояние способа связи, контакта и описания;
- условное отображение контактного поля;
- локальную проверку данных;
- экран благодарности;
- доступность и управление фокусом.

Страница хранит только состояние `storyDialogOpen` и передаёт компоненту обработчик закрытия. Тест и его модальное окно остаются независимыми.

## Тестирование

Автоматические тесты должны подтверждать:

- новые название и главный заголовок присутствуют в исходном интерфейсе и метаданных;
- обе кнопки `Рассказать о случае` открывают общую форму;
- выбор каждого способа связи показывает правильное поле и скрывает остальные;
- смена способа связи очищает старый контакт;
- пустые обязательные поля блокируют переход к благодарности;
- корректно заполненная форма показывает благодарность;
- закрытие окна очищает форму;
- Escape и клик по фону закрывают окно;
- обе production-сборки завершаются успешно: Sites и GitHub Pages.

Реализация выполняется через цикл red-green-refactor: сначала тест, который падает из-за отсутствующего поведения, затем минимальное изменение интерфейса.

## Публикация

После проверки обновление публикуется в существующий Sites-проект и в ветку `DEV` репозитория `RaymondSiberia/antihook`. GitHub Actions должен автоматически обновлять GitHub Pages из ветки `DEV`.

## Вне объёма этой итерации

- отправка данных на почту, в мессенджер, CRM или базу данных;
- постоянное хранение заявок;
- уведомления ответственному лицу;
- антиспам и CAPTCHA;
- юридические тексты согласия на обработку персональных данных.

Перед подключением реальной отправки потребуется отдельно определить получателя, политику хранения, согласие на обработку персональных данных и меры защиты чувствительной информации.
